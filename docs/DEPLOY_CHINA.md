# 国内访问方案与部署指南

> 背景：站点已发布到 GitHub Pages（https://bdydgz114514.github.io/），但 **github.io 域名在中国大陆通常无法直接访问**（被墙或极不稳定）。下面给出 4 种国内可用的方案，按「省事程度」排序。

## 方案 A（最省事）：单文件版，双击即看

文件：`李文亚Wiki_单文件版.html`（约 3.2 MB，单个 HTML，全部数据与样式都内嵌）

1. 下载该文件到 Windows（任意位置）；
2. **双击它** —— 用 Edge/Chrome 打开即可浏览；
3. 支持：首页 / 人物志 / 理论体系（含视频证据锚点）/ 事件年表 / 梗词典 / 视频库（1206 个视频的摘要、要点、标签、场景台词）/ 中文子串搜索。

优点：无需联网、无需安装、无需服务器。缺点：不包含逐场景的完整画面描述与 Pagefind 全文索引（那部分在完整版里）。

## 方案 B：离线完整版（ZIP + 一键启动）

文件：`李文亚Wiki_离线版.zip`（42 MB，含 1247 个页面 + Pagefind 全文搜索）

1. 解压到任意目录；
2. 双击 `启动Wiki.bat`；
3. 浏览器自动打开 http://localhost:8080/ 。

无需安装任何软件（有 Python 用 Python，没有就用 Windows 自带 PowerShell）。
注意：**不要直接双击 site/index.html**，站点使用绝对路径，必须经由本地服务访问。

## 方案 C：部署到国内静态托管（长期使用推荐）

站点是纯静态的（`site/` 目录内容即全部文件），放到任何静态托管都能跑。**必须部署在域名/站点根目录**（站内使用 `/_astro/...` 绝对路径）。

| 平台 | 是否需备案 | 大致步骤 |
|---|---|---|
| **Gitee Pages（码云）** | 不需要 | 注册并实名 → 新建仓库 → 上传 `site/` 内全部文件 → 仓库「服务 → Gitee Pages」→ 部署（免费版需审核，付费版即时） |
| **阿里云 OSS** | 绑定自有域名需备案 | 开通 OSS → 建 Bucket（读写权限：公共读）→ 上传 `site/` 内容 → 基础设置 → 静态页面（默认首页 index.html，404 用 404.html）→ 用 OSS 默认域名即可访问 |
| **腾讯云 COS** | 同上 | 建存储桶 → 开启「静态网站」→ 上传 `site/` 内容 → 设置索引文档 index.html |
| **Cloudflare Pages** | 不需要 | 免费；连接 GitHub 仓库（构建命令 `npm ci && npm run build`、输出目录 `dist`）或直接上传静态文件 |
| **帽子云（maoziyun.com）** | 不需要 | 国内 CDN 静态托管；见下方「方案 C-1」 |
| **Netlify** | 不需要 | 免费；把 `site/` 文件夹直接拖到 app.netlify.com/drop 即可 |

### 方案 C-1：帽子云（maoziyun.com）具体设置

帽子云支持「从 Git 仓库构建」和「直接上传静态文件」两种方式，本项目两种都能用。

**方式一：连接 Git 仓库构建（推荐，改站后自动重新发布）**

| 配置项 | 填写内容 |
|---|---|
| 仓库 | `bdydgz114514/liwenya-wiki`（**站点源码仓库**，根目录就是 Astro 项目） |
| 分支 | `main` |
| 构建命令 | `npm ci && npm run build` |
| 输出目录 | `dist` |
| Node 版本 | 20 或 22（LTS 均可） |
| 环境变量（可选） | `NPM_CONFIG_REGISTRY=https://registry.npmmirror.com`（国内装包更快）<br>`SITE_URL=https://你的域名`（让页面 canonical/OG 链接指向新域名） |

> 注意：**构建命令与输出目录两项必须填写**，留空会构建失败或发布空目录。
> 站点构建全程不访问外网数据（内容来自仓库内 `src/data/*.json`），只有装 npm 依赖需要网络。

**方式二：直接上传静态文件**

1. 下载 `李文亚Wiki_上传包.zip`（约 42 MB）并解压，里面的内容就是构建产物；
2. 在帽子云选择「静态文件上传 / 手动部署」，把解压后的**全部内容**（`index.html`、`_astro/`、`videos/`、`pagefind/` 等）上传到站点根目录；
3. 不需要填构建命令。

**共同注意**：必须部署在**域名根目录**。站内资源与页面链接使用 `/_astro/...`、`/videos/...` 这类根路径，若挂在 `/wiki/` 子路径下会丢样式。

## 方案 D：用你自己的服务器 / 本实例（已在跑）

本实例已经起好了两个服务（都是国内直连，速度最快）：

| 端口 | 内容 | 访问方式 |
|---|---|---|
| **8898** | **完整版 Wiki 站点**（1247 页 + 全文搜索） | 在 AutoDL 控制台把 8898 添加为「自定义服务」，用分配到的地址访问 |

## 常见问题

1. **为什么不能直接双击 `site/index.html`？** 站点使用 `/_astro/...` 等根路径引用资源，且搜索需要 http 协议；用 `file://` 打开会丢样式与搜索。请用方案 A 或 B。
2. **部署后样式全丢？** 说明没有部署在根目录（例如放在了 `/wiki/` 子路径）。要么部署到根，要么联系我改成子路径版本（需要改站内链接与搜索路径）。
3. **GitHub Pages 上的版本还要保留吗？** 建议保留：作为源码与国际化访问入口；国内用户走方案 A/B/C/D。
