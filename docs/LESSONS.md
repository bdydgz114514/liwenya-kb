# 经验教训（本会话实录）

> 本文档随项目推进持续追加，最终随知识库一并发布。记录的是**可复用的工程经验**，不是八卦。

## 一、环境与依赖

1. **pip 镜像要挑**：本机 `/root/.pip/pip.conf` 指向阿里云镜像，但 `yt-dlp`、`faster-whisper`、`rapidocr-onnxruntime` 在该镜像上「No matching distribution found」；换清华 TUNA 镜像（`-i https://pypi.tuna.tsinghua.edu.cn/simple`）后全部成功。**结论：装不上不等于包不存在，先换镜像。**
2. **`tail` 管道会吃掉输出**：`pip install ... | tail -3` 在超时被杀时什么都不会打印，导致「安装失败但看不到原因」。长安装任务应放后台并重定向到日志文件。
3. **CUDA 版本错配是隐形杀手**：faster-whisper/CTranslate2 需要 **cuBLAS 12**，而本机是 CUDA 13（torch 2.12.1+cu130，只有 `nvidia/cu13`）。表现为运行期报 `Library libcublas.so.12 is not found or cannot be loaded`。**对策：改用 transformers + bf16 的 Whisper 后端**（原生吃 CUDA 13），实测约 13 倍实时。
4. **transformers 的 Whisper 不能把 `initial_prompt` 放进 `generate_kwargs`**：会被 `_validate_model_kwargs` 判为未使用参数并抛错（逐条视频全失败）。正确做法是 `tokenizer.get_prompt_ids(text, return_tensors='pt')` 传 `prompt_ids`，或干脆不传。
5. **Whisper 默认输出繁体中文**：加 `zhconv.convert(text, 'zh-cn')` 后处理即可，成本可忽略。
6. **apt 源是华为云**，`ffmpeg`、`p7zip-full`、`p7zip-rar`、`unrar`、`unar` 都能直接装；安装时 ldconfig 会抱怨一批 0 字节的 `libnvidia-*.so` 存根，与本任务无关，可忽略。

## 二、媒体处理

7. **AV1 + 硬件解码报错是噪音**：`Your platform doesn't support hardware accelerated AV1 decoding` / `Failed to get pixel format` 由解码器探测产生，软件解码仍然成功；用 `grep -v` 过滤即可，不要据此判定失败。
8. **场景切分对单镜头视频退化**：PySceneDetect 对固定机位视频只返回 1 个场景，若「每场景 N 帧」会只抽到 N 帧。改为**按总时长分配帧数**（约每 12 秒 1 帧，上限 max-frames），长视频覆盖率才够。
9. **RAR5 分卷在传输中不可验证**：传输未完成时 `unrar l` 会报 `Unexpected end of archive`，7-Zip 报的 `Physical Size` 也不可信。**判据应该用文件大小**：定长分卷（本例 4000 MiB）到齐 + 尾卷稳定 2 分钟即可判定完成。
10. **中间产物要及时清理**：16 kHz 单声道 WAV 约 32 KB/秒，168.6 小时音频若全留会占约 19 GB；转写完成后立即删除。

## 三、模型与流水线设计

11. **VLM 输出画面文字非常可靠**：Qwen3-VL-8B 对中英混排的屏幕文字能逐字抄录（含英文小字与署名），这让「画面文字」这一路几乎不需要独立 OCR 兜底。
12. **先试点再全量**：用 3 个短视频（8s/15s/38s）跑通「切分→抽帧→VLM」再放开 1193 个，避免全量跑完才发现 bug。
13. **溯源优先**：所有理解结果都带 `asset_id + 时间戳 + 帧文件路径`，使得后续任何摘要都能回溯验证，也让「三次全面检查」有据可依。
14. **GPU 上多任务共存可行**：Whisper（约 8.5 GB）+ Qwen3-VL-8B（约 20 GB）在 96 GB 显存上可同时驻留，长任务不必串行等待。

## 四、工具与协作

15. **`grep` 在管道里是块缓冲的**：`cmd | grep ... | tee log` 会导致日志长时间为空，误判为「没跑」。要么加 `--line-buffered`，要么直接看数据库状态。
16. **状态看数据库比看日志可靠**：批处理用 SQLite 的 `asr_done/frames_done/vision_done` 标志位推进，进度与断点续跑都以此为准，日志只作参考。
17. **网络分区是常态**：`huggingface.co` 直连不通但 `hf-mirror.com` 通；`github.com` 通但 `wenyaverse.fandom.com` 不通（需换官方 GitHub wikitext 快照）。**采集前先探测可达性，并准备镜像/快照替代路径。**
18. **大文件传输可能来自容器之外**：`/proc/*/fd` 找不到写文件句柄时，说明写入方在宿主机侧（平台的文件传输通道），此时只能靠文件大小稳定性判断完成。
19. **凭据管理**：GitHub token 只存于 `/root/.github_token`（0600），仓库内严禁出现；`.gitignore` 显式排除；提交前用 `git grep` 与 `grep -r` 双重扫描确认无泄漏。

## 五、内容合规与伦理（本项目特有）

20. **区分「虚构设定」与「真实个人信息」**：参考 wiki 自身声明「内容为网友扮演/社群虚构」且「不对任何主张作真实性背书」，同时又出现具体居住社区名等私密信息——**知识库与站点必须主动剔除住址、健康、证件等隐私项，并保留原声明的中立口径**。
21. **同源站点要交叉验证**：wenyaverse.fandom.com 与 wiki.liwenya.com 的部分条目 wikitext 逐字节一致，可作为版本基准；引用时统一标注出处，避免把二手转述当一手事实。
22. **GPU 上多模型并用要看算力而不是显存**：Whisper 与 Qwen3-VL 同时驻留显存没问题（合计约 35 GB / 96 GB），但算力争抢让 ASR 从约 18 倍实时掉到 4.3 倍实时，ETA 从 9 小时涨到 39 小时。**结论：单卡上应串行跑重推理任务，先跑最长的那个。**
23. **CTranslate2 在 Blackwell 上不划算**：补齐 cuBLAS/cuDNN 12 运行库后 faster-whisper 确实能跑，但实测只有 5.1 倍实时，反而慢于 transformers + bf16 的 18 倍——新版架构上 CT2 的 kernel 优化没跟上。**装得上不等于跑得快，务必实测再选型。**
24. **进度要用「音频秒数/耗时」而不是「视频个数」估算**：短视频占比高时会严重高估吞吐（前 20 个视频看着 25 倍，实际 4.3 倍）。
25. **Whisper 会输出模板幻觉**：中文语音识别在音乐/静音/低信噪比段落会反复生成「请不吝点赞 订阅 转发 打赏支持明镜与点点栏目」「字幕志愿者 XXX」等模板句。必须做后处理过滤（本项目移除 993 条幻觉片段，占已转写片段的 10%）。
26. **更大的模型不一定更慢，更小的模型不一定更快**：large-v3-turbo 在本机 pipelines 流水线里实测 25.9 倍实时，与 large-v3 的 26.3 倍几乎相同——瓶颈不在参数量，而在 30 秒分块批处理与解码循环。既然速度一样，就选准确率更高的 large-v3。
27. **说话人筛选可以量化验证**：用 ECAPA 余弦相似度对照「最大簇质心」，他人创作内容只有 0.29，本人 0.65–0.74；训练出的翻唱从原唱 0.18 提升到 0.79，说明这条链路是有效的、可度量的。
28. **长任务要自动守望**：训练每 25 轮存一次档，用一个后台守望脚本自动「检测存档 → 提取小模型 → 出翻唱」，比人工卡点可靠（本次 6 个里程碑全部自动完成）。

## 附：AI 翻唱音频返工经验（v3 → v6）

29. **响度必须实测，不能靠脚本“看起来对”**：v3 里我用正则解析 `loudnorm` 的 JSON 失败，目标值静默退化成默认 -20 LUFS，结果 AI 人声 -21.6 LUFS、比原唱低 4.8 dB，被伴奏彻底盖住。**教训：任何自动化的响度/质量目标都要在执行后回读实测值并打印对比。**
30. **过度预处理会杀掉高音**：`deesser` + FFT 降噪 + 压缩的预处理链，使转换后高音区（90 分位）从 697 Hz 掉到 532 Hz——de-esser 会把高音当成齿音压掉。**做音色转换时，输入侧尽量“少动刀”，把清理放到输出侧且用温和参数。**
31. **基频提取器的适用域不同**：RMVPE 主要按语音训练，唱高音时跟踪失败（529 Hz vs 原唱 706 Hz）；换成 Praat(pm) 后同一段恢复到 702 Hz。**同一个任务换一个 f0 后端就能救回高音。**
32. **诊断音频问题要可量化**：LUFS（响度）、LRA（动态）、pyin 的 f0 分位（音域）、静音段底噪、频谱能量占比（音色亮度）——这五个指标足以定位“小/闷/吵/平/破”五类主观抱怨，无需靠耳朵反复试。
